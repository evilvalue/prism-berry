# Подпись сборок BerryTrip

## Что даёт самоподписанный сертификат, а что нет

Самоподписанный сертификат (`CN=BerryTrip`) **не является доверенным** на компьютерах пользователей.
Windows показывает для такого файла то же предупреждение SmartScreen, что и для неподписанного
(«Неизвестный издатель»), а антивирусы могут относиться к нему настороженно. Он полезен для:

- проверки целостности: подпись и файл `.cer` позволяют убедиться, что установщик не подменили;
- проверки самого процесса подписи перед покупкой настоящего сертификата;
- машин, где пользователь вручную добавил `.cer` в «Доверенные издатели» (см. ниже).

Убрать предупреждения у всех пользователей может только сертификат, выданный публичным CA
(OV code signing), и даже он первое время собирает репутацию в SmartScreen. Бесплатная
альтернатива для открытых проектов — SignPath Foundation (издатель будет «SignPath Foundation»,
нужны публичный репозиторий, CI-сборка и политика подписи).

## Самоподписанный сертификат (этот репозиторий)

```powershell
powershell -ExecutionPolicy Bypass -File packaging\make_cert.ps1
```

Скрипт создаёт сертификат в хранилище текущего пользователя и выкладывает в `packaging\codesign\`:

- `berrytrip-codesign.pfx` — закрытый ключ (пароль по умолчанию `berrytrip`, в git не попадает);
- `berrytrip-codesign.cer` — открытая часть, её можно раздавать вместе с релизом.

## Подпись файлов

```powershell
# exe из dist и последний установщик из logs
powershell -ExecutionPolicy Bypass -File packaging\sign_build.ps1 `
  -PfxPath packaging\codesign\berrytrip-codesign.pfx -PfxPassword berrytrip

# проверить подписи
powershell -ExecutionPolicy Bypass -File packaging\sign_build.ps1 -VerifyOnly
```

Скрипт сам находит `signtool.exe` в Windows SDK, подписывает SHA-256, при желании ставит
метку времени (`-TimestampUrl http://timestamp.digicert.com`).

## Чтобы предупреждение исчезло на конкретной машине

Пользователь (или вы) может добавить открытую часть сертификата в свои хранилища:

```powershell
powershell -ExecutionPolicy Bypass -File trust-certificate.ps1
```

Это `certutil -user -addstore Root` и `-addstore TrustedPublisher`. Делать это стоит только
если вы доверяете источнику сертификата: любой, кто получил закрытый ключ, сможет подписывать
свои файлы от этого имени. Поэтому `.pfx` никогда не публикуется.

## Настоящий сертификат

Если появится бюджет, порядок такой:

1. Купить OV code signing (Certum Open Source ~€49–69/год для некоммерческого OSS,
   SignPath Foundation — бесплатно для OSS, Azure Artifact Signing — ~$10/мес, но физлицам
   только США/Канада).
2. Пройти проверку личности/организации у CA.
3. Подписать тем же скриптом, передав `-PfxPath` нового сертификата (или `-Thumbprint`,
   если ключ в облаке/токене).
4. Подписывать все последующие релизы одним и тем же издателем — репутация SmartScreen
   накапливается между выпусками.
